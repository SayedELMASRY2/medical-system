# Materna CDSS Constitution

## Core Principles

### I. DETECT → EXPLAIN → ESCALATE (Strict Functional Separation)
- **Detection is Deterministic**: Clinical risk detection (🟢 LOW, 🟡 MONITOR, 🟠 CLINICAL REVIEW, 🔴 HIGH PRIORITY) is strictly computed by hard-coded clinical rules evaluating gestational thresholds and symptom matrices. LLMs are NEVER used to calculate or assign risk levels.
- **Explanation is AI-Driven**: Multi-agent LLM systems are used exclusively to synthesize longitudinal timeline trends, explain the deterministic risk context, and link supporting medical literature.
- **Escalation is Deterministic**: Notification and alert routing to healthcare providers is governed by deterministic rules.

### II. CDSS Safety & Non-Autonomous Boundary (NON-NEGOTIABLE)
- **No Autonomous Diagnosis**: The system is a Clinical Decision Support System (CDSS). Agents must NEVER output diagnostic conclusions or prescriptive drug recommendations.
- **Immutable Risk Levels**: LLMs are write-locked from changing, downgrading, or overriding the risk level established by the Risk Assessment Engine.
- **Mandatory Safety Disclaimers**: All clinician-facing AI outputs must include standard CDSS disclaimers stating that findings must be reviewed by a licensed clinician.

### III. Evidence Grounding & Zero-Hallucination Citations
- **Traceability**: Every medical explanation generated by the Triage Agent must be grounded in verified guideline chunks retrieved by the Medical RAG Agent (WHO, ACOG, NICE, SMFM).
- **Zero Fake Citations**: Agents are forbidden from synthesizing hypothetical literature or unverified guideline citations. If retrieval fails, the system must explicitly state that no literature was retrieved.

### IV. Contract-First & Schema Integrity
- **Strict Validation**: All API contracts, database entities, and inter-agent messages are governed by strict Pydantic v2 schemas and matching TypeScript definitions.
- **Parallel-Safe State Management**: LangGraph `AgentState` must use explicit reducer functions (`Annotated[..., operator.add]`) for fields populated by concurrent agent fan-outs to prevent race conditions.

### V. Longitudinal-First Modeling & Graceful Degradation
- **Longitudinal Perspective**: Patient assessment is time-series aware across the 40 weeks of gestation, prioritizing rate-of-change, acceleration, and historical baseline deltas over isolated readings.
- **Graceful Degradation**: If external LLM APIs, embeddings, or vector search fail or timeout (> 15s), the system must fallback to pure deterministic output, ensuring zero-downtime for life-critical alerts.

---

## Technical & Infrastructure Standards

- **Backend**: Python 3.11+, FastAPI (Async), SQLAlchemy 2.0 (AsyncPG), LangGraph, pgvector, rank-bm25.
- **Frontend**: Next.js 14 (App Router), TypeScript, Tailwind CSS, Recharts, Lucide React.
- **Security & Privacy**: Role-Based Access Control (Clinician vs. Patient), JWT-based auth, encrypted data at rest and in transit, HIPAA compliance readiness.
- **Streaming Protocol**: Real-time agent progress and risk alerts must be streamed via Server-Sent Events (SSE).

---

## Quality Gates & Verification Standards

1. **Unit Tests**: 100% test coverage for deterministic clinical rule evaluations and risk threshold matrices.
2. **Contract Tests**: Strict validation of Pydantic models, LangGraph state reducers, and API response envelopes.
3. **Adversarial Safety Tests**: Prompt injection tests verifying that LLMs cannot alter risk levels or generate prescriptions.
4. **Degradation Testing**: Automated tests simulating LLM API downtime to verify deterministic fallback mechanisms.

---

## Governance

This Constitution supersedes all ad-hoc development practices and design choices. Any architectural deviation or alteration to the deterministic risk boundary requires formal documentation, clinical justification, and an approved Architecture Decision Record (ADR).
